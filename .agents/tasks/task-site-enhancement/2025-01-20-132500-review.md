# Animation Enhancement Review

Framer Motion animations added across the platform - Hero, LessonCard, Roadmap, About, Ticker, Playground, and utility components. Transform and opacity are the primary animation properties, with `useReducedMotion` hooks in core interactive components.

**Watch for:** Two layout-triggering animations (`height: 'auto'` in LessonPage, `width: '100%'` in Playground) that could cause jank (likely). About.jsx and Ticker.jsx don't use `useReducedMotion` though the global CSS fallback mitigates this (confirmed).

**Verdict**: APPROVED

## High-level view

The build passes cleanly and the animation architecture is sound. Core components (Hero, LessonCard, Button, CodeEditor) properly gate animations behind `useReducedMotion()`, ensuring accessibility. CSS-level fallbacks in global.css provide a second safety net with `animation-duration: 0.01ms !important`.

Two animations deviate from transform/opacity-only patterns: an expandable docs block animates `height: 'auto'` and the Playground output animates `width: '100%'`. Both trigger layout recalculation, but the elements are small enough that impact is minimal on modern devices.

Navigation links (`#roadmap`, `#lessons`, route navigation) remain functional. State management in Playground (name, output, feedback, isRunning) works correctly.

<summary>Issues (2)</summary>

1. **Layout-triggering height animation** — LessonPage.jsx animates `height: 'auto'` on docs block expansion. Consider using `max-height` with a fixed value or Framer Motion's `layout` prop for smoother performance.

2. **Layout-triggering width animation** — Playground.jsx animates `width: '100%'` on output reveal. Could use `scaleX` with `transform-origin: left` instead.

### Reduced motion handling

Hero.jsx, LessonCard.jsx, Button.jsx, and CodeEditor.jsx all import `useReducedMotion` from framer-motion and conditionally disable complex animations. The approach is consistent: check `shouldReduceMotion` and either skip the animation or use instant transitions.

About.jsx and Ticker.jsx skip the hook but rely on the global CSS fallback. This works because the CSS rule `animation-duration: 0.01ms !important` applies universally, including to Framer Motion's CSS-based animations. The parallax scroll effects in About would still run their transforms, but these are minimal motion that shouldn't trigger vestibular issues.

### Animation property audit

Most animations use transform (scale, y, rotate, rotateX, rotateY) and opacity, which are composited on the GPU. The two exceptions:

```jsx
// LessonPage.jsx - docs block expand
animate={{ height: 'auto', opacity: 1 }}

// Playground.jsx - output reveal  
animate={{ opacity: 1, width: '100%' }}
```

Both trigger layout, but on small elements with short durations (0.3s, 0.4s). The practical impact is low, but for a polish pass these could be refactored.
